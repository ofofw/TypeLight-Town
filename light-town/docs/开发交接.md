## 3. 必须遵守的约束

这些来自需求方，交接后仍然有效：

- **线上发布需要需求方另行授权。** 不要部署到公网，也不要把代码推送到公开或远程仓库，除非需求方明确同意。
- 不使用付费服务或 API Key；不加账号、云同步、导入导出、广告、支付、社交、统计分析，不收集个人信息。
- 运行时不连接任何外部地址：字体、音频、图片都随包分发，不用 CDN。`tests/e2e/privacy.spec.ts` 会检查这一点。
- 素材必须原创或许可清楚。新增素材要写进[许可清单](许可清单.md)。不使用 macOS 系统语音（`say`），因为它的许可不允许再分发。
- 代码和文档里不留 TODO、占位内容或编造的测试结果。
- **模拟器结果不能写成 iPad 真机通过**，只能标“iPad 模拟”或“真机未验证”。
- 发现需求冲突时，先列出冲突和影响，和需求方确认后再实现。确认结果追加到 `需求澄清记录.md`。
- 不改动使用者的系统设置或浏览器设置，确实需要时先征得同意（例如 Safari 的“允许远程自动化”）。

## 4. 代码结构的关键约定

- **纯逻辑和界面分开。** `src/core/` 里都是纯函数：输入旧存档和当前时间，返回新存档，不碰 DOM、不读时钟、不访问存储。所有规则测试都在这一层（`tests/unit/`）。改规则先改这里，再补单元测试。
- **配置集中在 `src/config/`**：课程与手指（`keys.ts`）、建筑与街区（`buildings.ts`）、商品与主题（`shop.ts`）、奖励与时间（`rules.ts`）、词库（`words.ts`）、语音台词（`voice.ts`）、音频（`audio.ts`）。改数值时只改这里，`tests/unit/config.test.ts` 会按需求文档核对。
- **控制器** `src/app/controller.ts` 持有状态。每次状态变化后，它会立即写入 `localStorage`。
- **结算是原子的。** `settleLevel` 在同一次写入里清掉 `activeLevel`、发放奖励、推进建筑和课程。奖励按关卡 ID 和灯光节轮次 ID 幂等，所以在结果页刷新也不会重复发奖。相关测试的名称以“D02”开头。
- **存档**：
  - 键名 `lighttown.save`，备份 `lighttown.save.backup`，外层 `schemaVersion` 是 3，每位玩家内层是 2。
  - 读取时先严格校验（`src/core/save/validate.ts`），损坏就用备份。
  - 遇到更高版本的存档时只读、不覆盖。
  - 多个页面同时打开时，用 `lighttown.lease` 租约保证只有一个页面写入。
  - **改存档结构时**：升 `SCHEMA_VERSION`，在 `storage.ts` 里写迁移，并补测试。
- **随机**：出题用关卡种子（`src/core/rng.ts`），同一种子出同一组题。刷新后能回到同一题，靠的就是这一点。
- **输入**：按键分类集中在 `src/core/input.ts`，包括自动重复、组合键、大写、数字标点、输入法组字和空格。练习页的键盘监听在 `src/ui/usePracticeKeys.ts`。
- **美术**：全部是代码画的 SVG（`src/art/`），没有图片文件。`npm run art:preview` 可以导出预览图来检查。
- **音频**：用 Web Audio 播放。浏览器要求先有用户手势，所以“开始点亮 / 继续点亮”的点击和任意 `pointerdown` 都会解锁音频。语音播放时，音乐降到原来的 25%。加载失败时游戏照常运行，并显示重试按钮。
- **Safari 键盘差异**：Safari 默认按 Tab 不会停在按钮上，要按 Option + Tab。为防止打完最后一个字母后误按 Enter，结果页要求先用 Tab 选中按钮。这是有意设计的，不要“修”掉。

## 5. 环境里踩过的坑

| 现象 | 原因与处理 |
|---|---|
| 机器上没有 Node | 当初把 Node 官方包解压到了用户目录，不需要管理员权限。任何 22.12 以上的版本都可以。生成语音的脚本会直接读取 `.ts` 台词文件，需要 22.18 以上 |
| `npm ci` 提示 fsevents 的安装脚本 | `package.json` 的 `allowScripts` 已经禁止 fsevents 的安装脚本。它只用来监听文件变化，禁止不影响使用 |
| 端到端测试大批超时 | Mac 显示器休眠后，无界面 WebKit 会把点击送到错误的坐标。用 `caffeinate -du npm run test:e2e` |
| 端到端测试偶尔个别超时 | 和其他重负载任务同时运行时出现过，单独重跑全部通过。测试默认 3 个并行进程 |
| 4173 端口被占用 | Vite 设置了 `strictPort`。可以设 `E2E_PORT=4183`，让测试自己另起一个预览服务；也可以设 `E2E_BASE_URL` 指向已经在运行的服务 |
| iPad 用 `.local` 地址打开返回 403 | Vite 默认只接受 localhost 和 IP。已在 `vite.config.ts` 里用 `allowedHosts: ['.local']` 放行 |
| `npm run test:safari` 报 “Allow remote automation” | 需要在 Safari → 设置 → 开发者里勾选“允许远程自动化”，或者运行一次 `safaridriver --enable`。这要使用者本人操作 |
| 想检查 Safari 脚本本身的逻辑 | `CHROMEDRIVER=<chromedriver 路径> node scripts/safari-check.mjs --chrome`：在 Chrome 上跑同样的步骤，结果写到 `test-results/`，不进证据目录 |
| 语音模型、Whisper 模型很大 | 下载到 `scripts/models/`（已在 `.gitignore` 中），不入库。生成好的 `public/audio/voice/*.m4a` 已经入库，平时不用重新生成 |
| 双击打开游戏 | 构建会通过 `scripts/standalone.mjs` 生成内嵌脚本、样式、字体和音频的 `dist/index.html` 及外层 `index.html`；源码入口仍使用 Vite |

## 6. 测试证据怎么更新

`docs/evidence/` 里是交付用的证据。改动功能后，按需要重新生成，并同步修改验收记录、兼容性报告和交付说明里的数字：

| 证据 | 生成方法 |
|---|---|
| `unit-results.json` | `npx vitest run --reporter=json --outputFile=docs/evidence/unit-results.json` |
| `e2e-results.json` | `npm run build && caffeinate -du npm run test:e2e`，再把 `test-results/e2e-results.json` 复制过来 |
| `safari-real.json` | `npm run preview` 后运行 `npm run test:safari`，结果直接写入 |
| `screens/` | `node scripts/tour.mjs http://127.0.0.1:4173/ docs/evidence/screens/<目录> <宽> <高> chrome\|webkit` |
| `art/` | `npm run art:preview`，从 `.cache/preview/` 挑选 |
| `voice-report.json`、`voice-verify.json` | `scripts/voice/generate.py`、`scripts/voice/verify.py`（见 README“语音生成”） |
| `f01-clean-install.md` | 人工记录：从一份干净副本开始，按 README 安装、构建、测试 |

对外分享前，把两个 JSON 结果文件里的本机路径换成 `<仓库目录>`、`<用户目录>`（验收记录中有说明）。

改动代码后，要重新运行 `npm run build`，并提交更新后的 `dist/`。验收记录说明 `dist/` 与同一次提交的代码一致。
