# 质量门槛

命令从 `light-town/` 执行；先检查 package.json 和工具可用性。缺失工具或权限不等于测试通过。

## 按变更范围执行

|变更|必须证据|
|仅文档|相对链接存在、与引用源码一致、无互相矛盾规则|
|任何代码/配置|npm run typecheck；npm test；npm run build|
|页面/输入/状态/音频/构建|上项加 npm run test:e2e；node scripts/check-standalone.mjs|
|视觉/美术|上项加受影响页面前后截图，按 DESIGN.md 人工检查|
|存档结构|旧档迁移、损坏/高版本/不可写、多标签页、重复结算专项证据|

macOS 可用 `caffeinate -du` 包裹浏览器测试避免休眠；其他系统直接调用测试，不依赖此工具。浏览器缺失时列出缺项；Chrome 专项可使用 `--project=chrome`、本地文件专项可用 `--chrome-only`，但不能将其标记为全浏览器通过。iPad 模拟、WebKit 和真实 Safari/iPad 必须分开记录。

同时验证根 index.html 双击、源码 index.html 自动跳转、dist/index.html 独立打开，以及 HTTP 版本。真实浏览器中验证启动、输入、暂停、保存恢复和声音；音频解码通过不等于已试听。界面验收保留三种视口及缩放检查。

## 完成条件

1. 本次行为例子全部有实现或明确未完成说明，主流程和异常路径可达。
2. 相关测试通过；失败先复现、定位、修复，再重跑受影响范围。不得删断言、跳过失败用例或替换截图来掩盖回归。
3. 记录命令、日期、运行环境、通过/失败/未验证和证据路径；历史报告不作为本次证据。
4. 用户可运行的两份 HTML 与当前源码一致；改变运行方式时更新 README。
5. 同步受影响规范、许可及验收记录，指出真实风险和未验证平台。

测试数量从实际输出读取，不把固定的通过数当成完成标准。交付回复包含改了什么、如何打开、验证结果和未验证事项；不需要汇报无关内部操作。
