# 工程规范

## 分层与代码

沿用现有 React + TypeScript + Vite。依赖版本和脚本以 `light-town/package.json`、锁文件为准。复用已有结构，单个功能不顺带更换框架、状态管理或样式系统。

|层|职责|
|src/config|课程、建筑、商品、词库、时间、奖励、语音台词等配置|
|src/core|可独立测试的规则、生成、评分、统计、状态转换|
|src/core/save|存档校验、存储和租约边界，显式注入存储接口|
|src/app|控制器、副作用、浏览器平台和音频|
|src/ui|页面、交互、语义和焦点管理|
|src/art、src/styles|原创美术和共享视觉样式|

纯规则接受显式状态/时间/种子，不在其中访问 DOM、网络或系统时间。平台交互放现有边界模块；`core/save` 的存储适配不等于可以在评分函数中读 localStorage。UI 经控制器调用规则，不复制奖惩、晋级或存档逻辑。沿用显式 TypeScript 类型、判别联合和现有命名；禁止为消除报错大范围使用 any 或关闭检查。

## 存档兼容

维护 `lighttown.save`、备份、schemaVersion 和 lease 的约定。结构变化要提供旧版本样本、迁移、字段校验及失败恢复测试；不能通过清档解决升级问题。奖励/进度/关卡完成在一次状态提交中保存。保留多标签页所有权与 revision 检查，存储不可写时明示内存模式，不能虚报已保存。

## 两种运行方式

- `light-town/index.html`：开发入口；file:// 下转到 dist/index.html。
- `light-town/dist/index.html` 和项目根 index.html：构建生成的独立 HTML，脚本/样式/字体/图标/音频内嵌。
- `scripts/standalone.mjs`：构建后的打包；`scripts/check-standalone.mjs`：本地文件专项验证。

保持 IIFE/经典脚本及文件模式音频兼容，主脚本在 DOM 容器存在后执行。新资源须同时验证 HTTP 与 file://，不能只在开发服务器正常。修改源码后构建更新两份产物，不直接编辑压缩产物。文件迁移、不同浏览器和不同 URL 的存档隔离在使用说明中保留。

## 依赖、权限与素材

优先现有库；确有必要新增依赖时写明用途和体积/许可影响，维护锁文件。运行无需 API Key 或外部请求。新增美术和声音写入 docs/许可清单.md。遵守用户授权范围，不擅自部署、推送远程、修改系统或浏览器设置。可在任务中自行执行正常文件编辑、构建、测试和修复。

## 双玩家存档开发

涉及玩家身份、存档导入导出与清空时，按[双玩家规范](players-save/README.md)实现外层 v3 档案、全局租约、两人独立任务和恢复撤销。现有实现使用外层 v3、每位玩家内层 v2；`profiles.ts` 负责整组事务，`mapGame.ts` 显式映射外部字段，原 `storage.ts` 保留单人格式迁移与兼容测试。
