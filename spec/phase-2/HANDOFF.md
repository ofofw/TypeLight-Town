# 开发交接与验收

## 可直接交给开发工具的任务

在现有点亮小镇上实现 spec/phase-2/ 的第二阶段。先读取根 AGENTS.md、spec/README.md、phase-2/README.md、RULES.md、UI.md、content.json、本文。词句、拼音、任务内容以 content.json 为源，不运行时生成新英文。保留第一阶段与两种运行方式；完成 schema 迁移、72 个任务、委托专项、系统中文输入、共享奖励、家长记录、素材与全部验收。不得只完成页面或用占位动画/音频冒充成品。无需再询问教材或重新决定已定产品参数。

只开发本地项目，不顺带部署、推送或修改系统设置。新增规则分离成 phase2 配置与纯函数；共享组件按明确模式参数扩展，避免把第一阶段大小写归一与中文忽略行为全局替换。完成后构建两份独立 HTML，同步使用说明与实际验证证据。

## 实现顺序与工程入口

1. 导入固定内容，集中参数；运行本目录 validate.py。新增纯函数：故事/委托生成、完整文本评分、复习调度、奖励事务、统计汇总，并用边界样例单测。
2. 扩展存档判别联合、迁移旧档、租约与恢复；先验证第一阶段原有未完成关能够继续。
3. 实现原生输入框与 IME 提交门控；通过真实平台试验后接入故事，而不是最后才验证选字。
4. 实现路线、任务、结果、委托、专项及家长页，复用样式与建筑。
5. 制作 12 种生活动画和全部中文音频，记录许可；完成 file:// 打包与 HTTP 检查。
6. 执行下列验收，交付源码、产物、运行说明和证据。

## 必须人工记录的验证

- 真实 Mac Safari、Mac Chrome、真实 iPad + 外接键盘：记录 OS、浏览器、输入法、键盘布局及版本日期。覆盖 Enter 选字、鼠标/触摸选字、候选翻页、多音字、ü、移动光标、输入法切换、暂停/返回、后台恢复。
- 真实设备不可用时状态必须写“未验证”；不得用自动化 WebKit 或设备尺寸模拟替代“iPad 验证通过”。未验证项留在交付风险表，不隐瞒。
- 1280×800、1024×768、768×1024、200% 缩放与减少动画，逐页检查目标层级、拼音对齐、输入框、候选窗口、触摸按钮及故事反馈。固定种子、存档、主题，与原截图比较共用组件。
- 全部中文音频逐项试听：目标与读音一致，无截音、叠音，多音字读音正确。清点许可与内嵌资源。

## 命令与交付物

项目根运行 `python3 spec/phase-2/validate.py`。代码目录执行 `npm run typecheck`、`npm test`、`npm run build`、`npm run test:e2e`、`node scripts/check-standalone.mjs`。脚本以当前 package.json 为准，不把历史数量写成新的通过证据。

交付：修改后的源码及配置；根 index.html 和 light-town/dist/index.html；新增本地音频和许可；旧档迁移 fixture；自动化测试；实际日期/环境/结果的验收记录；Mac 双击及 iPad HTTP 操作说明。游戏完成与规格完成分开报告。本规格不证明代码已实现、设备兼容已通过或孩子已达到教学效果。
