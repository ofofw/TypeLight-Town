# 双玩家与存档备份开发规范

状态：已实现的功能规范。目标平台为 Mac，保留双击 HTML 与 HTTP 运行；无需安装程序。实现入口为 `light-town/src/core/save/profiles.ts` 与 `light-town/src/app/controller.ts`；实际验证范围见[验收记录](../../light-town/docs/双玩家与存档验收.md)。必读 [设计规范](../DESIGN.md)、[工程规范](../ENGINEERING.md)、[验收清单](ACCEPTANCE.md)。

## 产品目标

固定两名玩家在同一设备轮流玩，不做同局双人、联机或对战。每次打开或刷新先选玩家，卡片显示名字、角色、第一阶段已完成建筑数/12、第二阶段故事数/72、有无未完成任务。首次没有旧档时显示“玩家一”“玩家二”，两人均为新进度；已有有效单人档完整迁移给玩家一，玩家二从头开始。

自动保存到浏览器 localStorage，不自动写游戏目录。支持下载一个包含两名玩家的 JSON 备份文件和整体恢复；不提供单人导出、单人导入、合并或云同步。复制游戏文件夹不承诺复制或隔离浏览器存档。设置页明确说明“进度保存在当前浏览器；复制游戏文件不会带走进度，换浏览器或移动使用请导出备份”。

## 玩家规则

两个槽位固定，内部 profileId 使用持久随机 ID，不用名字作存储键。允许改名字：去首尾空白，1–12 个 Unicode 字符，拒绝控制字符、空名和与另一人相同的名字；按纯文本渲染，不允许 HTML。名字不是密码，也不形成隐私隔离。不提供新增第三人、删除槽位或玩家登录。

各自保存完整角色、设置、金币、装饰、主题、课程、建筑、统计、复习、两阶段任务、会话和奖励幂等信息。允许同角色，同一玩家换角色不改变进度。音乐、语音、减少动画等偏好跟玩家走；选择页静音，选定后应用该玩家设置，声音依浏览器用户手势策略启动。

首页及练习顶部持续显示玩家名字与角色。暂停菜单与首页都有“切换玩家”。切换时暂停计时和任务、停止声音、保存当前玩家并返回选择页；另一个玩家可拥有自己的未完成任务。每个玩家仍只能有一个跨阶段未完成任务，不要求为切换而放弃任务。回到玩家后提供继续任务或返回小镇，不自动恢复计时。

组字进行中切换时先提示“先选好字再切换，或放弃本次未选定的拼音”；选字完成才保存上屏文本。明确放弃组字不等于放弃任务，保留之前已上屏草稿；系统候选窗口无法恢复。切换页不触发第一阶段开场或任务完成奖励。

## 自动保存与失败

复用既有事件保存；第二阶段草稿最多合并 300ms，题完成、暂停、切换、失焦、恢复/清空确认均立即写。成功提示“已保存到此浏览器”，不得显示“已保存到文件”。不保证系统强杀前最后未提交的组字或 300ms 草稿能保存。

保存失败保留两名玩家完整内存快照，明显显示“尚未保存，关闭页面可能丢失进度”，提供重试、导出当前内存备份和取消切换。失败后不得默默加载旧磁盘状态覆盖内存。用户明确选择“暂存本次并切换”可在同一页面内切换，两份内存进度都保留并持续提示；刷新会有丢失风险。存储恢复后整体写入，仍须检查租约和 revision 冲突。冲突不允许强写，先导出本页快照，再加载其他页面的最新存档。

## 备份导出

设置页“备份与恢复”入口提供“导出两人备份”。导出前暂停当前任务、提交已上屏文字；如果仍在组字，先要求确认或明确放弃本次组字。导出 snapshot 来自当前有效内存（包括尚未能写入的进度），不会为了导出而重置任务、晋级或发奖。

文件名 `点亮小镇-双人备份-YYYYMMDD-HHmmss.json`，时间按本机当地时间；文件内容 exportedAt 为 UTC ISO 时间。使用 Blob 和浏览器下载，不依赖目录授权 API。反馈“已请求下载，请在下载位置确认文件”，不能假称已验证文件落盘。取消或下载失败不影响游戏存档。文件含两人名字与学习记录，不包含可执行脚本、音频、租约或系统路径。

文件格式：format 固定 `lighttown.profiles-backup`，formatVersion=1，exportedAt，appSaveVersion=3，profiles 数组恰好两项，每项包含 profileId、name、game；game 为完整合法 v2 SaveData。不得只导出可见进度而遗漏 activeTask、settled、storyDone、taskSeq、session、草稿或复习时间。界面中最后一次导出时间标记为“已发起导出”，不是文件可恢复保证。不强制提醒、不增加签到。

## 整体恢复与撤销

1. 选择 JSON 文件；读取前检查文件不超过 20 MiB，支持扩展名 .json（MIME 为空可接受）。只做 JSON 解析和白名单字段映射，禁止 eval、原型合并或执行内容。验证格式版本、两项档案唯一 ID/名字、每项完整 SaveData、合法枚举/范围/任务结构；不信任文件名、显示摘要或字段声明。
2. 验证成功后展示文件导出时间及两人的名字、角色、金币、建筑数、故事数，与当前两人并排比较。明确“将替换两名玩家的全部进度，不合并”。导入较旧文件可以恢复，但显示其早于当前进度的提示；新版本不支持时拒绝并保留原数据。
3. 点击“恢复这份备份”后再次明确确认覆盖两个人。预览期间当前游戏暂停；确认时重新检查租约、revision 和文件校验结果，期间存档变化则使预览过期，重新预览。
4. 在同一次主档写入中保存旧两人快照作为 undo，并替换 active profiles。成功后返回选择玩家页，无默认选中，不自动开始任务。失败不能替换可见进度或清除旧档，保留预览以便重试/取消。
5. 设置页提供“撤销上次恢复”，展示被恢复前两人的摘要，提示会丢弃恢复后新玩的进度，再确认。一次撤销恢复原两人，清空 undo，无重做。普通游玩、退出、刷新不清除 undo；下一次成功恢复替换 undo。清空任一玩家时同时清除 undo，确认框提示“也会删除上次恢复的撤销记录”，避免旧撤销重新带回被清空进度。

只接收本功能导出的双人格式；不接受任意网页数据或未封装的手工 JSON。浏览器现有 v1/v2 单人档通过自动迁移处理，不混入导入流程。重复导入同一文件仍是整体替换，不叠加任何金币；实例 ID 的旧请求不能作用于新存档。

## 清空某位玩家

设置页按钮注明“清空〔名字〕的游戏进度”，再次确认框列出将清除该玩家角色、金币、装饰、课程、记录和未完成任务；另一人不变。玩家名字与 profileId 保留，声音/减少动画等偏好保留，角色需重新选择。没有“一键清空两人”按钮。

作为受租约和 revision 保护的整体存档更新执行，严禁调用 localStorage.clear() 或沿用单档 removeItem 清空逻辑。为防止滚动备份把已清空进度恢复，写入前先删除本应用滚动备份，再写新主档并清空 undo；任一步失败即报失败，不宣称清空成功。删除备份成功但主档写入失败时原主档仍完整，允许重试。下一次普通保存的备份只能从已经清空后的主档生成。

## 存档结构与兼容

沿用 `lighttown.save` 主键、`lighttown.save.backup` 滚动备份和 `lighttown.lease` 租约键。主档升级为外层 schemaVersion=3：revision、createdAt、updatedAt、profiles（恰好两项）、undoRestore（null 或两人快照及 capturedAt）、lastExportRequestedAt。不持久化“当前选中玩家”；选择只在当前页面内。

profile={profileId,name,game}，game 保留 v2 完整 SaveData，包括其 schemaVersion=2。外层 revision 为整个双人档写入冲突判定；game.revision 是该玩家游戏快照版本，不用作全局锁。game.createdAt/updatedAt 保留原语义。外层 undo 与 profiles 不递归包含外层档案；导出不含 undo、revision 锁、lease 或 tabId。

v1 先经过现有 v1→v2 迁移，再封装给玩家一；v2 直接封装，所有已有字段完整保持。玩家二调用现有新档创建逻辑，不复制金币、角色、统计或已学内容。迁移保持 raw 源直到 v3 成功写入；失败继续只读保护/明确内存状态，不把旧档标为已升级。主档坏而备份有效时先恢复/迁移备份，不把坏档覆盖唯一好备份。未知高版本不写入、不清空、不降级。

普通保存顺序为：校验 ownership 和基线 raw/revision → 将当前有效 raw 写备份 → 将包含两玩家的新外层 JSON 单次 setItem 到主键。多个键不是同一事务；备份写失败则取消主档写入。主键单次写成功才视为本次保存成功。恢复 undo 内嵌在主档，不能分成两个需同时成功的键。最坏包含四个玩家快照，配额不足时完整报错，不能静默移除另一玩家或 undo。

读取按显式字段映射组装对象；未知扩展字段不执行，关键版本不兼容拒绝。旧代码读取 v3 应走其已有未来版本保护，不自动重置。旧版程序不支持新备份，不承诺跨版本向后导入。

## 多窗口和计分隔离

保留整个游戏一个活跃页面的全局租约（现有 5 秒心跳、15 秒超时）。即使两个标签选不同玩家，也不支持同时写档。接管后旧页暂停、禁止发奖/清空/恢复/改名。新页重新加载外层档并返回选人页。监听主档和 lease 的 storage 变化，不依赖改名后的存储键。

所有异步回调捕获 profileId、instanceId、存档 generation。切换、整体恢复、清空或接管后废弃旧回调，停止旧计时器和声音；禁止把上一玩家的晚到按键、结算或语音回调写入下一玩家。按键按住状态切换时清理。跨阶段奖励和购买继续只作用于当前 profile.game。

## 界面和交付范围

复用现有暖黄按钮、深蓝背景、原创角色和字体，不增新角色素材。两张玩家卡、名字编辑、顶部身份标签、暂停切换、备份恢复页、两人恢复预览及撤销确认是必做界面。昵称纯文本，错误信息不展示堆栈。触摸目标和键盘焦点遵循 DESIGN；Tab 可达，弹窗关闭返回触发控件。无未确认的默认覆盖选择。

本次仅要求 Mac Chrome 与真实 Safari 验证，不新增 iPad 交付要求；保留既有响应式代码，不以平台收窄为由破坏现有页面。保留根/源码/dist 三个入口及 HTTP。交付源代码、更新后的两个独立 HTML、迁移样本、测试、备份操作说明及实际验证记录。开发指令和验收见 ACCEPTANCE.md。
