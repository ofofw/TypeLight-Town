# 开发交接与验收

## 开发任务

按 [双玩家与存档规范](README.md) 在现有游戏增量实现：两名玩家轮流玩、每人独立角色和两阶段状态、每次先选人、逐人任务恢复、浏览器自动保存、整组文件导出/导入与撤销、指定玩家清空。导入导出不依赖云、服务器或目录授权，不新增桌面程序。不要改游戏课程参数、视觉风格或现有奖励。

先读取根 AGENTS 和 spec 入口，再实现纯迁移/格式校验/档案事务，接入控制器与 UI，最后构建和验证。当前单档 schemaVersion=2、固定存储键、全局 lease 为迁移基线。实现后同步用户说明和旧“无导入导出”提示，不能只新增按钮。

## 自动化验收

|编号|操作|结果|
|---|---|---|
|M01|真实 v1 单档与 v2 双阶段档分别升级|玩家一所有字段保留，玩家二全新，外层 v3|
|M02|迁移中配额不足|旧主档未被清空、不虚报成功，刷新可重试|
|M03|主档坏、备份好；两者坏；更高版本|分别恢复、明确重新开始/导入入口、只读保护，不自动覆盖|
|P01|新开、刷新游戏|总是玩家选择页，卡片摘要正确|
|P02|两人选同角色、改名|独立档案；空名/重复名/超长/控制字符拒绝；HTML 字符按文本|
|P03|玩家一半途切二，再切回|两人的任务/草稿/题序各自保留，不串音、计时或金币|
|P04|玩家一错误、领奖、购买；玩家二检查|所有游戏字段不受影响|
|P05|清空玩家一|保留其名字/ID/偏好；角色与游戏进度重置；玩家二完整不变；滚动备份/undo 不复活旧档|
|P06|清空失败/过期标签清空|不虚报成功，不删除另一人，拒绝过期写入|
|B01|两人均有不同阶段未完成任务，导出再导入|所有草稿、题目、统计、奖励防重字段完整恢复|
|B02|备份文件空、损坏、单玩家、重复 ID/名字、非法字段值、超过 20 MiB|拒绝，原档不变；有效 .json 的空 MIME 可导入|
|B03|备份版本较新|拒绝并解释需要更新游戏，不清空|
|B04|预览后取消或期间另一页改档|取消无变化；过期预览重新加载，不直接覆盖|
|B05|恢复完整两人并刷新|回选择页、值等于备份；undo 持久存在|
|B06|恢复后玩一段再撤销|二次确认后回到恢复前两人；清空 undo，无重做|
|B07|第二次恢复|undo 指向第二次恢复前快照，不积累无限快照|
|B08|重复导入、旧实例晚到结算|不叠加金币，不影响新 generation|
|B09|下载取消、用户未保存文件|游戏不变，不宣称文件已落盘|
|F01|存储不可写时练习、导出、内存切换|持续未保存提示，两人内存保留，文件包含当前有效快照|
|F02|全局 lease 被接管|旧页无法保存/结算/恢复/清空，新页选人|
|F03|切换时组字或按住 Enter|不误提交、不串玩家、已上屏草稿保留|
|F04|恢复主档写失败，或 undo 使配额超限|原档和界面不被半替换，允许重试和取消|

## 人工和浏览器验证

Mac Chrome、真实 Safari，分别通过 file:// 和 HTTP 完成：选人→两人各玩→切换→刷新→导出文件→在新浏览器档案导入→继续两人任务→撤销→指定清空。核对真实下载文件可再次选择，记录 OS/浏览器版本和日期。真实 Safari 不能用 Playwright WebKit 替代。

用现有 v1 fixture 和真实 v2 合法测试档覆盖课程、金币、装饰、第二阶段 storyDone、复习、maxObservedAt、settled、activeTask；逐字段比较，而非只比总金币。保存失败使用注入 KV 故障，不依赖真正耗尽磁盘。

运行代码目录的 npm run typecheck、npm test、npm run build、npm run test:e2e、node scripts/check-standalone.mjs。检查根 index.html、源码重定向和 dist/index.html；截图检查玩家选择、练习顶部、设置、恢复预览和确认框，共用页面不变形。缺少真实浏览器必须标为未验证。
