# 设计规范

## 视觉语言

深蓝夜空、暖黄灯光、奶白文字、青绿色辅助反馈；原创等距方块建筑和圆润伙伴，保留可辨识的建筑轮廓、屋顶、窗格、体积阴影。未亮建筑仍可辨认；关内临时光点与永久亮灯明确区分。新建筑复用 `src/art/` 的构造方式和明暗体系，具备自身轮廓和完成效果。

UI 色彩和尺寸从 `light-town/src/styles/global.css` 的 CSS 变量复用；美术从 `light-town/src/art/palette.ts` 复用。当前识别色包括天空 #0d1838/#1d2f6b、正文 #f7f2e6、主按钮 #ffc94d、面板 #1b2a5e、边框 #3e539a。修改这些公共值意味着全局视觉变化，应纳入明确范围，不能为单页方便随意覆盖。

中文使用现有系统字体栈；练习字母使用随包 Andika。正文基础 18px、行高 1.55；常规面板圆角 18px、间距变量 16px；标准按钮最小高度 48px、圆角 14px。优先复用现有 `.btn`、`.card`、`.page`、`.topbar` 等样式，不另造一套组件主题。触摸目标不得小于 44×44px。

## 页面与组件

- 页面保持清晰主操作和返回路径。复用 `Chrome.tsx`、`Dialog.tsx`、`Icon.tsx`，沿用 `pages/` 和 `components/` 分层。
- 练习页的视觉优先级：当前目标字母→按键和手指提示→练习进度→建筑/伙伴反馈。暂停、声音、帮助随时可用；统计、装扮和装饰不抢占目标区。
- 屏幕键盘大写键帽、小写角标，目标用小写；目标键以颜色、轮廓/指示符及手指文字共同标记。
- 按钮保留按下位移和边缘阴影；键盘焦点保留 3px 可见描边。禁用态有原因，加载、空数据、错误、完成状态均有实际文案和返回路径。
- 模态框管理焦点，关闭后返回触发处；键盘操作与触摸操作都必须可达。

## 动效、文案与声音

动效服务于反馈：输入立即改变光点，庆祝不超过 2 秒并可跳过；遵守减少动画设置。练习期间不叠加大规模地图动画、频闪或屏幕震动。文字用简短、具体的中文，例如“用左手食指按 F”“再找找看，没关系”；不责备、不虚构进步，不暴露内部异常堆栈或开发参数。

沿用现有音乐、音效和语音开关及音量体系；有用户手势后启动声音；语音播放时压低音乐，静音时保留文字图示。新音频需明确许可和随包分发，不使用未经核实可再分发的系统语音。

## 视觉参照和验收

现有截图位于 `light-town/docs/evidence/screens/`，参照索引见 `baseline.json`。修改前读取对应页面截图，并查看当前页面；截图是视觉参照，不等于当前运行状态。至少比较首页、伙伴选择、小镇、练习、结果、衣柜、家长页中受影响的页面。

保持 1280×800、1024×768、768×1024 和 200% 缩放可用。截图对比固定视口、种子、存档、主题和减少动画设置；记录允许变化的区域。检查字体、色彩、间距、按钮形状、建筑透视、信息层级及溢出。只跑布局测试不足以证明风格一致。未经授权的全局换肤、用 emoji 代替原创 SVG、将儿童界面改成数据后台均不符合规范。
